# Code Map

将需求、设计约束和行为场景映射到具体的代码符号，形成可追溯的实现证据链。

## 它是什么

Code Map（代码映射）是由 `implementation-mapper.md` 文件承载的归档产物。它在质量门通过后自动生成，记录了从设计到代码的完整追溯关系。

一份典型的 implementation-mapper.md 包含：

- **需求到实现映射** — 将 requirements.md 中的每条需求与实际变更的代码文件对应
- **行为场景到代码映射** — 将 behavior.md 中的每个 Given/When/Then 场景与实现它的代码文件和关键符号对应
- **全局依赖与例外证据** — 记录涉及全局共享文件的变更及其影响分析
- **验证结果摘要** — 包含类型检查、测试、漂移检查、Harden 审查的综合验证状态

## 为什么需要它

在传统的"设计-实现-测试"流程结束后，设计文档和代码之间的对应关系只存在于实现者的脑海中。当需要回溯某个设计决策为什么这样实现、某个行为场景由哪些代码支撑时，缺乏系统化的记录。

Code Map 在质量门通过时自动捕获这种追溯关系，形成从需求到设计到代码到验证的完整证据链。这使得后续的审计、回归分析和需求变更影响评估有据可依。

## 适用场景

- 归档时生成完整的实现追溯记录，作为 feature 完成的交付证据
- 质量门通过后，自动将 behavior.md 场景映射到变更代码文件
- 需要理解某个 feature 的哪些代码文件实现了哪些行为场景时，查阅映射表

## 与其他功能的关系

- Code Map 在 [质量门](/guide/how-it-works/quality-gate) 返回 Ready 或 ReadyWithDocUpdates 时自动生成
- 行为场景来源于 [BDD 与集成测试](./bdd.md) 的 behavior.md
- [合约与约束扫描](./contract-scanning.md) 提取的对齐项为映射提供模块和符号参考
- [设计漂移检测](./drift-detection.md) 的检查结果被纳入映射中的验证摘要
