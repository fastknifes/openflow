# 代码地图

## 是什么

代码地图是 Quality Gate 通过后自动生成的 `implementation-mapper.md`。它记录需求、行为场景和最终代码之间的对应关系。

它不是普通总结，而是一份可追溯索引：后续维护者可以从需求找到实现位置，也可以从行为场景找到相关代码与验证证据。

## 为什么需要它

功能完成后，如果缺少“需求 → 代码”的映射，后续变更就必须重新阅读计划、实现、测试和提交记录才能判断影响范围。这会增加维护成本，也容易让旧约束在新 Feature 中被遗漏。

代码地图让实现结果可追踪。没有它，归档后的知识会散落在多个文件中，后续约束扫描也更难准确理解历史功能的边界。

## 如何使用

当 Quality Gate 返回 Ready 后，OpenFlow 会自动生成 `implementation-mapper.md`。该文件通常记录：

- 需求条目对应的代码文件和关键符号
- `behavior.md` 场景对应的实现与验证证据
- 重要决策、约束或例外说明
- 后续变更需要关注的入口点

使用者通常不需要手动创建代码地图，但应确保行为场景、测试证据和实现文件足够清晰，否则映射质量会下降。

## 与其他机制的关系

代码地图与 [BDD 与集成测试](./bdd) 紧密相关，因为行为场景会被映射到具体实现和证据。

归档时，代码地图会复制到 `archive/`，供后续 Feature 的 [契约扫描](./contract-scanning) 读取，帮助新任务理解已有实现边界。
